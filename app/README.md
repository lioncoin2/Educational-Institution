# نموذج أولي (Visual Prototype) — تطبيق المؤسسة العالمية لتعليم القرآن الكريم

تطبيق Flutter **واجهات فقط**، عربي بالكامل مع دعم RTL، مبني Mobile-first ويعمل على Web و iOS و Android.
الغرض منه تجربة فكرة المنتج والـUX قبل بناء النظام الحقيقي.

> **المصدر الوحيد لمعلومات المؤسسة:** `../docs/institution-profile.pdf`
> **المحتوى المستخرج حرفياً:** `../docs/pdf-content-extract.md`
> **المواصفة الكاملة:** `../docs/prototype-spec.md`

---

## ⚠️ ما ليس في هذه المرحلة

لا Firebase · لا مدفوعات · لا بث مباشر · لا شهادات حقيقية · لا إشعارات على شاشة الجهاز (Push) بعد ·
لا تسجيل صوتي ولا اختيار ملفات على الجهاز بعد (واجهات جاهزة، والحزم مؤجّلة — انظر أدناه).

**بدون خادم** (الوضع الافتراضي ونسخة GitHub Pages): كل البيانات في الذاكرة، والتطبيق يعمل
**بلا إنترنت إطلاقاً** — حتى CanvasKit والخطوط محزّمة داخله — والمحادثات تجريبية ومعلَّمة بذلك.

**مع خادم** (`API_BASE_URL`): الرسائل وتسجيل الدخول حقيقيان — أول ميزة مربوطة بالخادم.
والرسائل تصل **فوراً** عبر اتصال مباشر (WebSocket) ما دام التطبيق مفتوحاً؛ وإذا انقطع الاتصال
يعيد التطبيق الاتصال تلقائياً ويجلب ما فاته من الخادم.
و**الإشعارات حقيقية** كذلك: مركز إشعارات محفوظ على الخادم (رسالة جديدة، محادثة جديدة، إضافتك
إلى محادثة)، وشارة واحدة لعدد غير المقروء على جرس الرئيسية والبرامج وفي «حسابي» تتحدّث فوراً،
وإعدادات لكل قناة. النقر على إشعار يفتح المحادثة بعد أن يتحقّق الخادم أنك ما زلت تستطيع رؤيتها،
وإلا يظهر «هذا المحتوى لم يعد متاحًا.».
و**البيانات الأكاديمية حقيقية**: الأقسام والبرامج والحلقات من سجلات المؤسسة على الخادم، و«مساري»
و«الحلقة» و«حسابي» تُظهر تسجيلك الفعلي — القسم والحلقة ومعلّمتها — **دون أي نِسَب تقدّم**، لأن
الحضور والإنجاز لا يُسجَّلان بعد (ولا تُخترع أرقام). الدروس والتقدّم والشهادات والإعلانات ما زالت تجريبية.

## 🚀 التشغيل

### المتطلبات

- Flutter **3.47.5** أو أحدث (Dart 3.13+)

```bash
flutter --version
```

### 1. تثبيت الحزم

```bash
cd app
flutter pub get
```

### 2. التشغيل على الويب (الأسرع للتجربة)

```bash
flutter run -d chrome
```

> إن لم يكن Chrome متاحاً:
> ```bash
> flutter run -d web-server --web-port 8080
> ```
> ثم افتح `http://localhost:8080`.

### 3. التشغيل على iOS / Android

```bash
flutter run -d ios        # يتطلب macOS و Xcode
flutter run -d android
```

### ربط التطبيق بالخادم (الرسائل والإشعارات والبيانات الأكاديمية)

```bash
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:3000
```

- العنوان فقط، لا أسرار: التطبيق لا يحمل أي مفتاح.
- للويب: أضِف أصل التطبيق إلى `CORS_ORIGINS` في إعدادات الخادم (مثلاً `http://localhost:8080`).
- الحسابات ينشئها طاقم المعهد (`/admin/users`)؛ لا يوجد تسجيل ذاتي.
- الرموز (tokens) تُحفظ في الذاكرة فقط في هذه المرحلة: إعادة تحميل الصفحة تتطلب الدخول من جديد.
  التخزين الآمن (Keychain / Keystore) مؤجّل — انظر `docs/architecture/messaging.md` §19.
- الاتصال المباشر يُشتق من العنوان نفسه (`http` → `ws`، `https` → `wss`، المسار `/realtime`)،
  ويُرسَل رمز الدخول في أول رسالة على الاتصال — لا في الرابط أبداً.
  تفاصيل البروتوكول وإعادة الاتصال والتعامل مع الرسائل المفقودة: `docs/architecture/realtime.md` (الجزء M).
- الإشعارات تصل على الاتصال المباشر نفسه (لا اتصال ثانٍ)، وتُحفظ على الخادم فلا يضيع منها شيء
  إذا كان التطبيق مغلقاً. الإشعارات على شاشة الجهاز (Push) لم تُفعَّل بعد: لم يُختر مزوّد
  (FCM / APNs)، ولم تُضَف أي حزمة Firebase — التطبيق جاهز لها عبر `PushTokenSource`.
  التفاصيل: `docs/architecture/notifications.md`.
- الأقسام والبرامج والحلقات تأتي من الخادم (`/academic`). هيكل المؤسسة يُهيَّأ على الخادم مرة
  واحدة بأمر صريح (`npm run academic:seed-structure`) من الملف التعريفي المطبوع نفسه: 9 أقسام و45 حلقة.
  **هذا هيكل الملف التعريفي المطبوع، وهو مؤقّت**: وصف المالكة الأحدث (سبعة أقسام أساسية، 10 حلقات
  أساسية لكل قسم، مدينة التهجي) لم يُطابَق بعد ولم يُنفَّذ — `docs/owner-information.md` و
  `docs/architecture/academic-reconciliation.md`. المسار المقفل وعبارة «المستويات» والشهادات في
  العرض التجريبي عيّنات، لا قواعد انتقال أو إتمام.
- التسجيل في الحلقات وتكليف المعلّمات **عمل إداري** على الخادم؛ التطبيق يعرض ولا يسجّل — لا يوجد
  تسجيل ذاتي لأن المؤسسة لم تقرّره. الطالبة غير المسجّلة ترى ذلك صراحة، دون حالة «بانتظار التسجيل».
- قبل تسجيل الدخول تعرض الرئيسية والبرامج هيكل المؤسسة كما في الملف التعريفي، وتتحوّل إلى سجلات
  الخادم بعد الدخول؛ و«مساري» والحلقات تطلب تسجيل الدخول. التفاصيل: `docs/architecture/academic.md`.

### 4. بناء نسخة ويب للمشاركة

```bash
flutter build web --release --no-web-resources-cdn
python3 tool/serve_web.py 8080     # ثم افتح http://127.0.0.1:8080
```

> **لماذا `--no-web-resources-cdn`؟** يمنع Flutter من جلب CanvasKit وخط Roboto من CDN خارجي.
> بدونه لن يعمل التطبيق على شبكة مغلقة، والمرحلة الحالية تمنع الاتصال بأي خدمة خارجية.

> **لماذا `tool/serve_web.py` وليس خادماً عادياً؟** التطبيق يستخدم مسارات حقيقية (`/programs/...`)
> لا `#/`، فيحتاج الخادم إلى إرجاع `index.html` لأي مسار غير معروف (SPA fallback).
> عند النشر على استضافة ثابتة مثل GitHub Pages، انسخ `index.html` إلى `404.html`.

### 5. الفحوصات

```bash
flutter analyze     # يجب أن يعطي: No issues found!
flutter test        # 392 اختباراً
```

## 🏗️ البنية

```
lib/
├── main.dart                     نقطة الدخول
├── app/                          الجذر، التوجيه، المسارات، إعدادات النموذج
├── core/
│   ├── theme/                    الألوان · الطباعة · المسافات · الثيم
│   ├── extensions/               اختصارات context.colors / context.text
│   └── widgets/
│       ├── foundations/          البطاقة · الشارة · التقدّم · الحالات · شارة البيانات التجريبية
│       ├── layout/               الغلاف المتجاوب · خلفية الكنتور · شريط الإجراء السفلي
│       └── patterns/             سلّم المسار · بطاقة الحلقة · صف الدرس · شبكة الأجزاء …
├── data/
│   ├── models/                   نماذج غير قابلة للتغيير، كلٌّ يحمل مصدره
│   ├── sources/
│   │   ├── profile_data.dart     🟢 محتوى حقيقي من الملف التعريفي (مع رقم الصفحة)
│   │   └── mock_data.dart        🟡 بيانات تجريبية فقط
│   └── repositories/
│       ├── repositories.dart     العقود المجرّدة
│       ├── http/                 التنفيذ على الخادم (عند ضبط API_BASE_URL)
│       ├── academic/             محوّلات: البيانات الأكاديمية ← نماذج الشاشات الحالية
│       └── mock/                 التنفيذ في الذاكرة (العرض التجريبي)
├── providers/                    Riverpod — ربط المستودعات بالشاشات
└── features/                     شاشة لكل مجلد (splash · home · programs · …)
```

### من أين تأتي البيانات

الشاشات لا تعرف مصدر البيانات؛ `providers/app_providers.dart` وحده يختار التنفيذ:

```
الشاشات → Providers → CatalogRepository · LearningRepository · …
                         ↓ (محوّلات data/repositories/academic/)
                   AcademicRepository → HttpAcademicRepository  (مع خادم)
                                      → MockAcademicRepository  (العرض التجريبي: هيكل الملف التعريفي)
```

- **الكتالوج** (الرئيسية، البرامج، تفاصيل القسم) يُقرأ عبر `AcademicRepository` في الوضعين؛ وفي العرض
  التجريبي يطابق ما كان عليه حرفاً بحرف.
- **مساري والحلقات والتقدّم وحسابي**: مع خادم تُقرأ من سجلات المؤسسة عبر المحوّلات؛ وفي العرض
  التجريبي تبقى ببياناتها التجريبية المعلَّمة.
- تصميم الشاشات لم يتغيّر؛ كل شاشة تعرض ما تحمله البيانات فقط (لا صفّ لمعلومة غير معروفة).

## 🟡 البيانات التجريبية

القاعدة: **كل بيان ليس في الملف التعريفي معلَّم بوضوح.**

- المحتوى الحقيقي في `profile_data.dart` فقط، وكل عنصر يحمل رقم صفحته.
- البيانات التجريبية في `mock_data.dart` فقط، ولا تناقض الملف أبداً: عدد الحلقات المولَّد
  مطابق تماماً لما ورد (5 و10 لكل قسم)، والأجزاء 30، والمتون ثلاثة.
- في الواجهة: شارة كهرمانية **«بيانات تجريبية»** على كل عنصر تجريبي، وشارة خضراء
  **«الملف التعريفي · ص…»** على المحتوى الحقيقي.
- عناوين الدروس مركّبة من مفردات الملف نفسه (الحروف، الحركات، مخارج الحروف، القراءة الصحيحة،
  التلاوة، الإتقان) حتى لا يُخترع منهج.

- **مع خادم** لا تُعلَّم البيانات الحقيقية بشارة تجريبية، ولا يُعرض تقدّم غير مسجَّل: لا نِسَب، ولا
  «أتممتِ 3 من 10»، ولا مواعيد، ولا دروس. قسمٌ لستِ مسجّلة فيه لا يُعرض «مكتملاً» ولا «مقفلاً» —
  فشروط الانتقال والإتمام لم تحدّدها المؤسسة بعد.

لإخفاء الشارات عند عرض نظيف: `AppConfig.showMockRibbons = false` في `lib/app/app_config.dart`.

## 🌐 النشر على GitHub Pages (معاينة فقط)

يوجد Workflow جاهز في `.github/workflows/deploy-pages.yml` ينشر **البناء الحالي** كما هو
على GitHub Pages — لا تعديل على الواجهات أو المعمارية أو الوظائف، ولا Backend ولا أسرار.

**كيف يعمل:**
- يُبنى المشروع في الـrunner بـ`flutter build web --release --no-web-resources-cdn`.
- `--base-href "/<اسم المستودع>/"` لأن موقع المشروع على Pages يُقدَّم تحت مسار فرعي.
- تُنسخ `index.html` إلى `404.html` (SPA fallback) ليعمل الفتح المباشر لأي مسار عميق.
- النشر عبر `actions/deploy-pages` باستخدام `GITHUB_TOKEN` التلقائي فقط.

**التفعيل (مرة واحدة، من صاحب المستودع):**
1. المستودع **خاص (private)** — وGitHub Pages للمستودعات الخاصة يتطلب خطة مدفوعة
   (Pro/Team). على الخطة المجانية، اجعل المستودع **عاماً (public)**:
   Settings → General → Danger Zone → Change visibility → Public.
2. Settings → Pages → **Build and deployment → Source = GitHub Actions**
   (يحاول الـWorkflow ضبطها تلقائياً عبر `actions/configure-pages`).
3. إذا فشل النشر برسالة حماية البيئة (Branch not allowed):
   Settings → Environments → `github-pages` → Deployment branches →
   أضف الفرع `claude/quranic-education-app-prototype-gkzle8` (أو اختر All branches).

**الرابط بعد النجاح:** `https://lioncoin2.github.io/Educational-Institution/`
