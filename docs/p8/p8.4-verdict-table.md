# P8.4 verdict table — GREEN / YELLOW / RED / UNKNOWN

**Status:** DESIGN — requires approval before implementation. **Single source of truth** for every
threshold, gate parameter and sizing factor used by the watchdog (design §9), the result verdict
(design §11, §13), rung prerequisites (design §14) and generator sizing (design §16). Code encodes this
file once (`backend/test/load/observe/rules.ts`, each rule with an `id` and `classHint`); no other module
or document may restate a number.

## Sampling semantics

- Samplers read every **5 s**.
- **Gauges** (CPU %, MemAvailable, load, conntrack, FD counts, health): *sustained* = **4 consecutive
  samples** (t … t+15 s, the plan's "> 15 s" [P §9]).
- **Rates/deltas** (drops, errors, packets): *sustained* = **3 consecutive 5 s windows**.
- **Above the RED level but not sustained = YELLOW**, and such a YELLOW is never "acceptable".
- Open windows keep being evaluated until **teardown start + 15 s**, so a breach late in a 30 s hold is
  not silently dropped.
- Deltas are measured from the **rung baseline** (taken after pre-run checks, before the publisher
  connects).

## Decisions from the pre-commit real validation

Evidence: local real-adapter validation on the SUT (publisher + 1 and + 2 listeners; generator,
LiveKit and controller sharing one host) — [p8.4-precommit-validation.md](p8.4-precommit-validation.md).

- **D-11 — G-lag band: DEFERRED (decided 2026-10-05).** G-lag keeps its provisional [NEW] bands
  unchanged (GREEN < 50 ms, YELLOW 50–200 ms, RED > 200 ms sustained) until the real off-box generator
  calibration at S1/S2; the GREEN edge is not widened. V-gen semantics are unchanged: a generator
  observation outside GREEN in the hold (or the 15 s lookback) makes the rung UNKNOWN, and the G-lag
  safety abort is unchanged. *Evidence only, not a calibration:* a real rtc-node worker with 1–2
  participants on the shared SUT host measured lag p95 3–79 ms per 5 s window (final-code run A: four
  windows of 68–79 ms → UNKNOWN on V-gen; run B: ≤ 36 ms → GREEN), against 1–6 ms for bare Node on the
  same host; the worst stalls followed `getRtcStats()` (decoded synchronously in JS, one call 287 ms)
  and correlated host pauses (41–61 ms). Local runs that are UNKNOWN on G-lag stay UNKNOWN.
- **D-12 — exact host CPU meter: APPLIED (decided 2026-10-05).** S-cpu-hot, S-cpu-total, G-cpu and
  G-cpu-hot, and the V-sampler E4 reference, use per-core **wall − idle − iowait**, where idle and
  iowait come from the kernel's NO_HZ idle clock (exact, in-progress idle included) and wall is the
  sampler's monotonic clock bracketing a synchronous `/proc/stat` read (`observe/cpu-meter.ts`). Busy is
  ≤ its window by construction (no value can exceed capacity) and floored at 0. Thresholds unchanged.
  `/proc/schedstat` `rq_cpu_time`, the source first proposed, was rejected on measurement: it is
  credited when a task is switched out — a pinned 100 % core read 0 % in 6 of 12 500 ms windows and up
  to 460 % in others (E4 against it false-fired in 3 of 12), while the idle clock read 100.0 % in every
  window and matched schedstat's mean on bursty load (27.9 % vs 27.5 %). S-cpu-hot judges exact
  hottest-core busy (no exact `%sys+%soft` exists on this kernel); the tick-sampled `%sys+%soft` is
  kept as the record-only S-cpu-sysSoft. A sampler refuses the meter when the kernel runs `nohz=off`.

## Rung verdict — safety and classification are separate

1. **Safety:** every RED rule aborts immediately (design §20), whatever the classification turns out to be.
2. **Classification** (first match wins):

| Verdict | When |
|---|---|
| **UNKNOWN** | Any validity check (V-*) failed. The RED rule that aborted, if any, is recorded as `safetyAbort` with its class hint. |
| **RED** | Validity held **and** a SUT rule (S-*) fired, or a media rule (M-*) fired while every generator signal was GREEN, or cleanup could not be verified. |
| **YELLOW** | No RED/UNKNOWN cause; at least one YELLOW signal (including over-RED-but-not-sustained); all gates held for the full hold; cleanup verified. Reported as the plan's **WARNING** band. |
| **GREEN** | Every signal GREEN for the full hold; validity held; cleanup verified. The plan's **SAFE** band. |

## Capacity statement

- The plan's rule is "stop climbing at the first WARNING; quote the SAFE number" [P §8, §10]. The P8.4
  instruction allows "GREEN or acceptable YELLOW". Reconciled as follows:
  - The **SAFE capacity** quoted is the highest GREEN rung with every lower rung GREEN [P].
  - A YELLOW rung **stops the ladder** by default. Continuing past it, or claiming it as "acceptable
    YELLOW", needs an explicit approval for that rung **[NEW deviation from the plan]**, and the claim is
    labelled WARNING-band, never SAFE.
  - "Acceptable YELLOW" additionally requires: hold ≥ 60 s; zero counter increments in the second half
    of the hold; every gauge's second-half max ≤ first-half max + the noise band measured at S2; and the
    verdict names each YELLOW signal [NEW].
- Every statement carries its profile (design §14). Never extrapolated.
