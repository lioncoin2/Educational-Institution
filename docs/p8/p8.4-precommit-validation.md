Defects found by the real runs and fixed (each with a regression test):

1. **Tone pacing** (adapter): the publisher fed 10 ms frames from `setInterval`, ignoring
   `captureFrame`'s backpressure; timer drift starved the source → silence and phase jumps
   (received tone ratio 0.01 over 1 s). Now a sequential producer awaits each `captureFrame`
   (measured ≈98 frames/s, tone ratio 1.000 per 100 ms block).
2. **Probe detector**: one phase-coherent 1 s window cancels on normal playout phase shifts (0.65 vs
   1.00 per block) → median of 100 ms block ratios.
3. **E4 reference** (errata E9): tick-sampled `/proc/stat` busy under-reads exact runtime → E4 now uses
   `/proc/schedstat`; samples carry `cpuRunNs`. *Superseded 2026-10-05 (D-12): schedstat is credited at
   switch-out (a pinned core read 0–460 % per window); E4 and the CPU rules now use the NO_HZ idle clock
   (`cpuClockMs`, observe/cpu-meter.ts).*
4. **Sampler series identity**: samples were regrouped by hostname, mixing the SUT with a co-located
   generator and two agents sharing a hostname (cloned VMs) → each sampler is judged on its own series.
5. **V-ticket window**: the whole access log was counted (a day-old JS-SDK line from the same address)
   → only lines at or after the run start, live log and rotation.
6. **Ramp burst** (found by B1): the token bucket's clock started at prepare, so phase A's ~15 s became
   credit and every listener was admitted in one tick (500/s measured against 2/s) → the clock starts at
   the first grant; `rampRate.actual` is now the inter-admission rate over the ramp's **grant** times (it
   hid this as 9.4/s; measuring issue times instead over-reported a cold run as 22.7/s of 20/s).

## Intermittent test failure — diagnosis

Reported: 1 of 8 full-suite runs failed in `fleet-monitor` and `fleet-controller`, cause unknown.
Investigated with a matrix (affected suites × normal / cold Jest cache / full parallel suite / every
core saturated), keeping the full output of every failing run. It reproduced twice, as **two distinct
real defects** — neither was "just timing", and neither fix widens a timeout or loosens an assertion:

7. **SUT sampling overlap** (`fleet/monitor.ts`), captured in a normal run: `missing` =
   `sut:S-cpu-hot`, `sut:S-tx`. `RunMonitor` sampled the SUT from `setInterval` with no in-flight
   guard; a sample slower than the interval (10 ms in the test, 5 s in production on a loaded SUT)
   overlapped the next, the later-started one finished first, and the "current" sample carried OLDER
   counters than the previous one → clamped/negative deltas → null metrics. Fix: never overlap (a slow
   sample delays the next); a sample completing after `stop()` is discarded. Regression: a fake-timer
   test with a deferred SUT port (fails with 5 overlapping calls when the guard is disabled).
8. **Stale lag re-judged as sustained** (`fleet/run-context.ts`, `fleet/agent.ts`), captured in a
   normal run after fix 7: safety abort `G-lag > 200 (4 consecutive samples)`, samples
   `[392, 392, 392, 392]`. The controller kept a **running maximum** of worker lag per agent and the
   agent re-used each worker's latest window, so one real stall (here worker start-up under a busy test
   machine) was re-judged on every later sample until it "sustained" → a fabricated RED and abort; in
   production any single >200 ms stall would have aborted a healthy rung. Fix: each worker window is
   consumed once (`FreshWorst`); a sample with no new window leaves G-lag **unobserved** (no band, streak
   kept, not missing — a new watchdog input) while every other generator rule is still judged.
   Regression: watchdog and monitor unit tests, plus an integration test whose fake worker stalls its
   event loop once for 400 ms (`LAG` marker) — with the old running max it fails with the captured
   signature (`[380, 380, 380, 380]`), with the fix it passes.

9. **Unhandled EPIPE on a dead agent link** (`fleet/session.ts`, `fleet/agent-main.ts`,
   `fleet/channel.ts`), captured in a full-suite run on 2026-10-05: `write EPIPE` thrown from
   `writeMessage` while an agent had exited. A write to a closed pipe fails asynchronously as an
   `'error'` event; nothing listened, so in production an agent dying mid-rung (an SSH drop) would have
   crashed the controller — no cleanup, no result — and a controller gone would have crashed the agent.
   Fix: the session treats an agent-stdin error as a lost link (the existing `onLost` abort path), the
   agent treats a stdout error as its bounded stop, and a read-side stream error ends the link once.
   Regression: a session test with a dead stdin, a real `agent-main` process whose stdout is closed
   (exit 0 via the stop path), and a channel read-error test — each fails without its handler.

The first real validation's `V-gen: G-lag` results were also inflated by defect 8 (after one window over
50 ms every later sample was judged YELLOW); D-11 is re-measured after the fix (verdict table).

D-12 re-validation (2026-10-05, the two runs above): on the real SUT sampler the exact meter had a CPU
clock in 49/49 samples, windows of 499–619 ticks, hottest core 6–28 % and total 1.5–16 % (always within
[0, 100]); one fully idle core's remainder was −0.58 tick (idle flooring, inside the 2-tick bound) and
read 0; E4's margin (exact host busy − watched processes) was ≥ 123 ticks in every window. The
tick-sampled `%sys+%soft` diagnostic read ≈ 5–6 % on the hottest core where exact busy read ≈ 21 %.

Decided 2026-10-05 (verdict table): **D-11** G-lag band DEFERRED to the S1/S2 off-box calibration (bands
unchanged; the measurements above are evidence only); **D-12** exact CPU meter APPLIED (NO_HZ idle clock).
