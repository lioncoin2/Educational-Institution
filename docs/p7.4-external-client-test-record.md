## Test tooling (and a viewer limitation worth recording)

- **Control plane:** operator `curl` against the API (login, start, hands, grant/revoke, screen-share claim,
  join-ticket mint, end). Join tickets are short-lived (`LIVE_JOIN_TOKEN_TTL_SECONDS` = 600 s here) and were
  minted immediately before each connect.
- **Media clients:**
  - Basic matrix (tests 1–15): **LiveKit Meet** `https://meet.livekit.io/custom` (desktop = teacher,
    iPhone/Safari = student). Note: the default meet landing page joins LiveKit's **demo** room — only the
    `/custom` page connects to our server with a pasted URL + token.
  - TURN relay (tests 16–17): the disposable **P7.4 LiveKit Test Client**, which exposes
    `Force TURN relay (iceTransportPolicy:'relay')`.
- **Viewer limitation (not a product limitation):** the P7.4 client served as a **claude.ai artifact renders
  inside a sandboxed iframe where WebRTC is blocked** — `livekit-client` reports *"LiveKit doesn't seem to be
  supported on this browser"* on both iOS and desktop. Running the **same client HTML as a local file**
  (`file://`) in a top-level desktop browser works normally. The relay tests were therefore driven from the
  local-file client. This is a constraint of the artifact viewer, not of the Live domain or the client code.

### TURN relay / D2 — resolved

Forcing `iceTransportPolicy:'relay'` made the client gather **only** relay candidates; the server then
reported the **selected** ICE pair as a `udp relay` candidate with `connectionType:"turn"` for **Chrome,
Edge, and Firefox**. This closes the P7.2 open question **D2** (Firefox-over-TURN-relay): Firefox media
traverses the TURN relay successfully. Server-side TURN termination was already verified in P7.3; this adds
the real-client relay confirmation across three browser engines.

## Notes / residual

- **Stronger real-world variant of test 17** (a network that actually blocks UDP 7882 / TCP 7881, e.g. strict
  cellular or guest Wi-Fi) was **not** exercised; `iceTransportPolicy:'relay'` forces the same relay path and
  is accepted here as proof that relay works. Running it from a genuinely UDP-blocked network remains an
  optional field confirmation.
- **Screen sharing from a mobile web browser is not possible** (Safari/Chrome on mobile cannot capture a
  screen); test 10 was driven from a desktop browser. This is a web test-tool limit only — the native Flutter
  app is expected to screen-share on iOS (ReplayKit), Android (MediaProjection) and Desktop/Web, and the
  backend session/token/permission model is already platform-agnostic and supports all of these unchanged.
