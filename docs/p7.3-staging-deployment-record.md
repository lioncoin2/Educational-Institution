  `institution_default` (`172.30.0.0/24`, gateway `172.30.0.1`, pinned via compose IPAM);

- **Images pinned by tag + digest:** livekit `@sha256:6fd3b708…`, postgres:16 `@sha256:1a6ab3f5…`
  (16.15), redis:7 `@sha256:c6eabf74…` (7.4.11).
- **nginx:** public `:443` → `stream` SNI demux (`ssl_preread`), TURN hostname → L4 TLS
  terminator (`:8444` → `127.0.0.1:5349`, PROXY protocol), everything else → HTTPS/WSS vhosts
  (`:8443` → API `:3000` / LiveKit `:7880`). PROXY protocol **v1** (nginx stable; LiveKit accepts
  it). `:80` serves ACME + redirect.
- **TLS:** one Let's Encrypt SAN cert for all three hostnames, auto-renewing (certbot timer),
  key readable only by root. Expiry 2027-01-01.
- **LiveKit:** `bind_addresses: [127.0.0.1, 172.30.0.1]` (signalling never public),
  `use_external_ip: false`, `auto_create: false`, `enable_remote_unmute: false`,
  `NODE_IP=213.136.65.135`. TURN via env: UDP 3478, TLS 5349 (`external_tls`), PROXY protocol on
  (trusted `127.0.0.0/8`), relay range **30000–32767**.
- **Secrets:** six distinct per-environment secrets in git-ignored `infra/env/staging.env`
  (mode 600): `JWT_SECRET`, `STORAGE_SIGNING_SECRET`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`,
  `POSTGRES_PASSWORD`, `REDIS_PASSWORD` — all ≥32 bytes, JWT/storage/LiveKit mutually distinct.
- **Migrations:** `drizzle-kit migrate` from a checkout against `db` (14 migrations, 29 tables).
  The image never migrates.
- **Firewall (ufw):** public `22,80,443,7881/tcp` + `7882,3478/udp`; internal
  `172.30.0.0/24 → 7880/tcp`; default deny incoming / allow outgoing. SSH untouched.
- **Host tuning:** `net.core.rmem_max/wmem_max = 16 MiB` for LiveKit media.

## Owner decision recorded (2026-10-03)

**TURN relay range 30000–32767/udp is NOT opened publicly** — per the design (§2/§6 "never
public"). Under host networking the relay's only peer is the local SFU (`NODE_IP:7882`), delivered
over loopback, so the range is not needed publicly; this overrides the mission's firewall line that
listed it as public. TURN control (3478/udp, 5349-via-443) is reachable; relays stay host-local.

### NOT VERIFIED — external client required

- **Browser media and the NAT/TURN matrix A/B/C, especially the Firefox-over-TURN-relay path**
  (the D2 question). This needs real browsers on real restrictive networks; it cannot be exercised
  from the server. The server-side `rtc-node` test proves the SFU media path, not a forced relayed
  browser allocation.
- **The application-authority criteria over live media** (listener cannot publish; moderator with
  `live.speak` can; student cannot screen-share; identity server-generated; display name from
  AccountDirectory; raise-hand/promotion; LiveSession-end cleanup; unauthorized/arbitrary room or
  permission rejected) are enforced in code and covered by the backend suite
  (`test/api/live-security.api.spec.ts`), which passes — but that is contract-level, not a live
  browser session. End-to-end confirmation also needs an external client.

## BACKUP AUTOMATION NOT YET IMPLEMENTED

Postgres (`pgdata`) and uploaded files (`api-storage`) are **system of record** but have **no
off-VPS, encrypted, tested backup**. A named volume is not a backup. Cadence, retention, encrypted
off-VPS destination and a restore test are owner decisions (design §8). Redis is ephemeral and
needs none.

## Recommended hardening (not blockers)

- `turn.deny_peer_cidrs` to restrict TURN relaying to `NODE_IP` (close the open relay).
- Give `/health/ready` real DB/Redis checks (currently dependency-free; observability debt).
- PROXY protocol **v2** would need nginx mainline (stable sends v1).

from real networks; browser-level authority verification; and the hardening above. Promote only
